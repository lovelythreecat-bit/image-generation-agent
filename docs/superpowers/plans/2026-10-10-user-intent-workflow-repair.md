# 商品生图工作流修正开发计划

> 执行状态：用户已批准并开始执行；代码修复和离线回归已完成。一次真实验收在素材分析阶段收到 HTTP 401，生图调用为 0，实际出图效果尚未验收。所有工作在当前工作区进行，没有执行 Git 命令或创建分支/worktree。

**目标：** 用户输入商品信息和图片后，系统提取关键信息、优化生成提示词、调用生图模型；商品外观保持不变，用户文案与创意被准确落实，失败时直接提供可理解的中文原因。

**方案：** 修正已有素材分析、长图策划和失败显示链路，不另建一套生成系统。原始输入完整进入提示词优化，模型提取的信息只作辅助；删除逐句来源匹配等不符合需求的阻塞条件，保留商品外观、用户指定内容及必要技术检查。

**技术栈：** 现有 Python 3.12、Pydantic、LangGraph、Tkinter、pytest、Ruff；计划不新增依赖。

**需求依据：** 本文件“已确认边界”记录本次对话已确认的需求，作为各任务的共同验收依据。

## 已确认边界

- 商品图片决定商品的形状、结构、颜色、图案、标识和已有细节，创作不能修改这些外观。
- 用户提供的卖点、营销文案和场景创意属于直接创作要求，不要求证明、不按现实常识纠正、不自行弱化或加免责声明。
- 例如用户要求商品猪飞在天上：可以表现原商品悬空飞行，不能擅自增加翅膀或改变商品身体结构。
- 用户明确规定的文案原样保留；其他文案可以提炼改写，但不能增加用户未提供的型号、参数、价格、认证、功效等具体主张。
- 分析结果不能覆盖原始用户输入，不能把模型建议、教学示例或旧任务内容当成本次商品事实。
- 检查的核心是商品是否被改变、用户要求是否遗漏或被改写、系统是否擅自加入内容；不检查创意是否符合现实常识。
- 真实图片无法辨认的部位不补造细节；在现有素材支持的画面内完成创作。
- 修改范围限于这些问题影响到的已有普通商品/商品长图路径及错误显示入口，不重做界面或旧独立长图系统。
- 不删除历史任务，不自动覆盖用户输入，不要求用户重新整理成程序内部的事实编号或来源格式。
- 只运行受影响范围的测试和最低必要静态检查。全量回归需另获明确授权。

## 验收标准

1. 用户无需补内部来源引用、事实编号等字段，正常输入能进入生图阶段。
2. 用户提供的文字信息不被图片分析替换；用户创意不因常识矛盾被删改。
3. 商品外观仍以原图为准，不因创意要求或模型建议改变结构、颜色和标识。
4. 无关教学细节和旧任务内容不会被静默注入提示词；未知外观不被系统当作确定事实。
5. 正常优化无需连续四轮策划调用，失败/恢复不盲目重复已付费生成。
6. 用户在主要结果界面直接看到中文失败阶段、原因及可执行处理办法；原因未知时如实说明。
7. 至少一次真实任务完成核验，或准确记录外部阻碍及中文错误显示；不声称已生成未生成的图片。

**可靠性边界：** 计划解决程序可控的无谓阻塞、信息污染和错误表达；外部接口仍可能超时、限流或拒绝请求。遇到这些情况必须清楚解释并保留可恢复结果，不承诺永远不失败。
