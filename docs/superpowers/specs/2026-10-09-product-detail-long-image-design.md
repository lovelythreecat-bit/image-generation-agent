# 长图能力设计草案（已被通用方案替代）

> 本文是此前的商品详情方案记录。用户已确认第一版覆盖通用场景；当前设计见 [通用图文长图设计](2026-10-09-general-long-image-design.md)。以下内容不再作为实施依据。

日期：2026-10-09

状态：待用户审阅；尚未修改产品代码。

## 目标与已确认范围

用户希望 image-agent 支持完整图文长图，已选择自动规划内容、生成配图并统一排版的方案。淘宝商品介绍是最初的示例；用户随后明确指出长图不应局限于淘宝，有多种应用场景。

核心能力应独立于特定平台：结构化内容规划、统一视觉风格、分段配图、文字排版、整图合成和切片导出。商品详情是已有项目可直接接入的应用；品牌介绍、活动宣传、使用教程等是否纳入第一版，正在向用户确认。此范围问题未确认前，不将这些额外场景视为已授权的实现要求。

成功标准是获得包含标题、卖点、场景、细节以及用户提供的参数等内容的连续商品详情页，可以向下浏览、查看分段，并保存用于后续上传。成品的中文文字清晰，商品外观与素材一致，失败和未审核的配图有明确状态。

以下是第一版建议，尚未由用户逐项确认：沿用现有中文 Windows 桌面工具、CLI 和 Python API；保留现有三张独立详情图功能；提供可配置的长图宽度和切片高度。商品详情接入不能限定淘宝和天猫，需覆盖项目现有平台；其他场景不应强制绑定电商平台。宽 750 像素仅作为商品详情初始默认值，不能硬编码为通用长图尺寸，也不宣称是平台当前强制要求。

## 现有流程

- `models.py` 中的输出类型为 `main_image`、`detail_page` 和 `pdd_white_background`。
- `prompt.py:build_targets` 为 `detail_page` 固定生成 scene、feature、closeup 三张图片。
- `pipeline.py` 和 `graph_nodes.py` 负责素材分析、证据选择、生成、保存候选、逐图审核、修复和成组审核。
- `graph_runtime.py` 和 `run_store.py` 保存任务、图片哈希、预算与检查点，并处理恢复及人工接受候选。
- `output.py`、`contracts.py`、桌面工具与 CLI 共同处理结果交付。现有输出校验和三图成组审核不能直接用于任意段数的长图。
- 已有 Pillow、中文 Tkinter 界面和模型结构化响应处理，无需新增 Web 服务或数据库。

## 方案选择

推荐采用 **AI 规划内容和生成配图，Pillow 排版文字与组装长图**。

模型负责理解商品素材、规划各段用途、组织文案及生成风格一致的商品图片。程序负责中文绘制、换行、间距、参数表、分段合成、整图与切片导出。页内标题和介绍不交给生图模型绘制，商品原有标签和图案仍按素材保留。

其他方案的取舍：

1. 让模型直接生成一整张极长图片，调用流程简单，但受供应商尺寸限制，中文、参数和局部修改难以控制。
2. 让模型生成含文字的分段海报再拼接，画面更自由，但中文准确性和跨段文字样式仍依赖生成质量。

推荐方案更适合现有审核与恢复机制，也能准确保留用户指定文案。第一版使用固定版式规则，由规划选择段落与配图角色；不引入可拖拽设计器或任意 HTML 模板执行。

## 使用方式

桌面输出类型增加“商品详情长图”。选择后显示长图宽度、风格、切片高度，以及可选的商品参数和售后说明输入。

用户仍可只添加商品素材、名称、分类和创作要求。参数、尺寸、材质、认证、优惠、售后承诺等不作为必填项；缺少时不创建对应内容。用户希望必须包含某项却没有提供内容时，显示需要补充输入。

“分析素材”展示现有素材分析与新增详情页策划：分段顺序、每段标题、文案、配图用途及统一配色。用户可修改输入并重新分析；生成时复用匹配的策划快照。第一版不加入单独的段落拖动和文案编辑器。

生成结束后，预览可在整张长图、排版后的分段、原始配图之间切换。整图提供缩放、适应宽度和纵向滚动；默认使用缩略图，避免把全部原尺寸长图载入 Tkinter 预览。原文件可通过现有打开图片或输出目录操作查看。

CLI 使用 `--output detail_long_image`；新增对应的宽度、风格、切片高度和参数 JSON 文件等输入选项。Python API 与 JSON 请求使用同一套模型及验证。

## 请求、策划与结果

商品详情暂按新增输出类型 `detail_long_image` 设计，不改变现有 `detail_page` 的三图行为。排版模块和布局数据使用与平台及商品无关的命名；若用户确认第一版包含通用内容场景，需相应改为通用 `long_image` 请求与场景模型，避免让教程或品牌介绍必须提供商品名称、分类和电商平台。

请求新增可选 `detail_long_options`，只在选择长图输出时启用：

- `width`：默认 750，允许 600–1500 像素。
- `theme`：`auto`、`clean`、`warm`、`premium`，默认 `auto`。`auto` 优先采用用户要求、参考风格和已有创意策划。
- `slice_height`：默认 1500，允许 500–3000 像素；切片为连续像素分割，保证按顺序拼回后与整图完全一致。
- `product_specs`：有序的名称和值列表，最多 30 项；用户填写的值保持原意及数字。
- `service_notes`：用户提供的售后说明列表，最多 10 项。
- `font_path`：可选中文字体路径。未提供时查找支持中文的系统字体；没有可用字体时在付费生图前报告可操作的错误。

新增结构化 `DetailLongPlan`：包含版本、规划来源指纹、主题令牌、按顺序排列的 `sections`。每段有稳定 `section_id`、角色、标题、正文或要点、参数行、配图描述，以及引用的素材或事实 ID。配图角色与版式角色分开，参数表和售后说明允许没有生成图片。

默认内容结构为商品首屏、核心卖点、使用场景、细节展示，另外仅在有输入时加入参数和售后说明。策划根据品类和素材调整顺序及必要内容；总段数为 4–8，每个平台最多生成 6 张不同配图。没有支持某个商品视角的素材时，选择已有视角的构图变化，不臆造背面或内部结构。

`MaterialAnalysis` 增加可选长图策划；旧分析没有此字段仍可读取。长图请求复用旧分析而没有策划时，在生成前补做一次规划并保存，不把缺失策划当作已完成。

`Asset` 增加具有默认值的资产来源字段，区分模型生成图片和本地合成图片；本地合成不伪造模型生成尝试或图片审核报告。新增可选合成元数据，记录输入资产 ID、输入哈希、策划版本、宽高、段落边界和本地排版检查结果。

每个平台最终长图作为 `detail_long_image` 的默认资产，配图、排版段落和切片作为具有稳定 variant 的关联资产。它们分别标明状态及用途，CLI 和桌面给出成品汇总，不把所有关联资产都称为独立长图。

结果新增可选长图策划及页面检查列表；同步更新请求 DTO、结果 DTO 和 JSON Schema。请求继续使用 1.0、结果继续使用 2.0，通过可选字段扩展；继续读取旧 1.0/2.0 结果。新增字段具有默认值，不改变旧字段含义。旧版本客户端不承诺能够识别新输出类型，README 必须说明使用长图需升级库。

## 文案规则

保留项目现有 `MARKETING_POLICY`：用户提供的营销声明和数字作为创作输入，不增加证明要求、弱化措辞或免责声明。规划和本地排版准确保留用户指定的文案。

模型可以补充段落标题、过渡语和有素材依据的描述，不增加用户没有提供的性能、认证、销量、折扣或售后承诺。参数表只使用用户填写的数据，不能从图片猜测尺寸或成分。

用户明确要求某句话原样展示时保存原文，并由本地绘制；检查这段原文是否出现在排版内容中。超出排版容量时报告具体段落和输入，禁止静默截断。

## 规划、生成与统一风格

请求长图时，在素材分析的结构化响应中附带 `DetailLongPlan`，复用当前分析调用。普通请求不增加必需规划字段或额外调用。长图策划响应缺失或格式错误时沿用现有一次格式纠正机制，仍失败则明确报告规划失败，不提交图片生成。

规划指纹包含影响策划的素材、商品信息、创作要求、参数、售后信息、平台及主题。平台只作为商品详情场景的适用约束，不控制通用排版模块。宽度和切片高度只影响本地渲染，不使素材事实过期；改变这些参数应允许复用策划并重新排版。必须保留现有 explicit selection 对素材分析快照的验证。

各段按配图角色编译证据与提示词。复用既有图像生成、参考容量约束、商品外观审核和定向修复。文案不作为新增商品外观的证据；生成配图不承担页内中文标题的绘制。

页内场景、光线、色调和人物设定共享。第一张审核通过的适用图片建立视觉参考，后续图片沿用已有场景连续性机制；参考容量优先保障商品证据，降级时记录警告。参数表等文字段落使用相同主题令牌。

## 本地排版与导出

新增独立的通用排版模块，输入为已验证的内容区块、主题、可用配图字节、字体和选项，输出为分段图片、整图、切片及布局元数据。模块不读取平台名或商品分类，不访问 API、修改预算或自行选择候选。商品策划转换为通用区块后进入排版；后续场景复用同一模块，不复制一套长图合成流程。

使用少量明确版式：首屏、卖点图文、场景图文、细节图文、参数表、售后说明。依据实际文字测量换行并计算段高，统一左右边距、文字层级和配色。配图默认等比完整呈现，不为填满版式而裁掉商品。

中文正文在 750 像素宽度下默认不小于 26 像素，字号随导出宽度等比调整。支持长中文、数字与单位、换行及长英文串；不靠无限缩小字体容纳正文。布局检查覆盖文本越界、区域重叠、空段、缺图及尺寸上限。

最长高度为 16000 像素，像素数量同时受宽度和高度上限约束。超出上限时返回排版错误并保存已生成配图，不截断正文或偷偷减少段落。分段后合成，及时释放中间图片，避免并行持有多张原尺寸长图。

整图、排版段落和切片默认使用 PNG，确保文字清晰，且切片按顺序拼接后与整图像素完全一致。元数据记录编码设置和切片范围。第一版不额外提供 JPEG 导出设置；如平台对格式或文件大小有不同要求，用户需要在实际上传前处理。本地成品写入使用现有原子保存方式，路径必须在任务目录内。

## 审核、失败与恢复

AI 配图沿用逐图审核与修复。长图不进入固定三张的 `audit_detail_set`。页面检查关注段落覆盖、原文保留、布局边界、输入状态以及风格参考降级等已有警告，不新增一次对缩小后的整张长图进行商品细节审核的模型调用。

仅当必需配图均自动通过、本地排版与文件保存成功时，最终长图为 `succeeded`。某张必需配图不存在时保留已有素材与策划，不将缺段的页面交付为成功。

配图存在但处于未通过或未审核状态时，可生成候选长图用于预览，并继承最严重的输入状态，保存到候选目录。候选不计入成功交付；页面中不额外绘制审核水印，状态在界面、JSON 与 DTO 中传递。

存在人工接受的配图时，最终合成结果最多为 `accepted`，不能转为自动通过。接受或恢复审核使选中配图发生变化时，根据输入哈希使旧合成缓存失效，再进行本地合成；这项操作不重新调用生图模型。

在现有 LangGraph 中增加独立的长图合成阶段，放在配图处理和现有组图审核之后、最终汇总之前。合成阶段出错时关联到页面资产，不能误标最后一张配图失败。未选择长图时不进入该阶段。

检查点保存完整策划、配图引用、布局元数据、已完成的合成资产以及缓存指纹。恢复时验证文件哈希；已保存配图不重复提交。只因本地排版或保存失败而恢复时重新执行本地阶段，图片预算不变化。

继续使用当前调用预算。分析格式纠正、补做规划和每次生图均如实计数；长图的图片调用数依据规划配图数展示，不以一张最终成品暗示只产生一次生图费用。

旧任务恢复保持原有执行路径和状态含义；旧终态不因新增长图阶段重新运行。长图新任务在终态恢复审核及人工接受后，需要判断是否重建合成资产。

## 修改范围与验证

预计新增长图策划验证和排版模块，修改 models、contracts、vision、selection、prompt、pipeline、graph_nodes、graph_runtime、run_store、output、desktop_runtime、desktop、CLI 和公开导出；同步更新 Schema、README 与示例。只修改与长图必要关联的流程。

验证覆盖：

1. 模型与契约：旧请求及结果兼容、不同平台的适用约束、字段边界、结构化规划失效、DTO 图片交付及长图状态。
2. 文案：用户指定原文及数字保持，缺失参数和售后不补写，模型额外声明不进入参数表。
3. 排版：真实中文字体、长文本、表格、多种宽度、段落边界、最高长度、内存上限和可逆切片范围。
4. 管线：仅长图、主图与长图、三张详情图与长图并存；规划生成次数、配图失败、审核异常、预算不足和保存失败。
5. 恢复：配图保存后中断、合成中断、已完成任务恢复、人工接受后重建，以及旧任务恢复不受影响。
6. 入口：桌面请求构造、切换与滚动预览、CLI 参数、JSON 请求和 Python API。
7. 视觉验收：使用离线替身生成至少一份真实字体的商品详情长图，检查整图和各段实际渲染效果；跑相关测试、现有回归测试和 Ruff。

真实模型出图效果、商品一致性及平台上传验收需要单独的真实 API 样例验证。离线测试不代表模型质量；未执行真实调用时明确说明。设计与实现期间不自动读取密钥并提交付费调用。

## 第一版范围外

不包含平台后台自动上传、自由拖拽编辑器、任意 HTML/CSS 模板、PSD 导出、批量 SKU 文案套版或跨任务重新挑选图片的管理界面。其他内容场景的第一版范围需结合用户对上述范围问题的回答确定；不能将“更多应用场景”自动解释为实现全部场景。
