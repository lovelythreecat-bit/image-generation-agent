# LangGraph 图片任务重构设计

日期：2026-09-30。状态：用户已逐项确认范围、接口、审核原则、重试及真实验收预算；按本文件执行。

## 目标与范围

在现有仓库完整迁移全部平台、主图、详情组图、白底图、桌面、CLI 和 Python API。使用真正的 LangGraph StateGraph 组织可恢复执行，复用已有 HTTP、图片及证据处理模块。先验证主图，再覆盖完整功能。迁移完成后不得保留两套生产编排。保留旧请求入口和主要参数；结果允许版本升级，新状态必须可解释。历史 JSON 可查看，不承诺旧任务续跑。不要求引入完整 LangChain，不新增 Web 服务。

## 已确认的产品原则

- 每个可解码候选在审核前保存；候选、自动通过和人工接受分别位于 candidates/、approved/、accepted/。每次尝试单独保存，不覆盖历史。
- 商品身份和可验证的必需外观是硬要求；仅来自宣传文案的功能声明不可强制 must_show，应报告不可验证。不得靠虚构磁环等结构通过审核。
- 审核异常不等同质量失败，重审原候选，不重复生图。达到预算后允许恢复，但不得重置累计调用预算。
- 默认最多 2 轮质量修复。基于具体失败项、理由、原图及上一候选制定可执行修复；保留已正确部分。相同失败且无新可执行策略时提前停止。2 轮是上限，不承诺每轮只调用一次 API。
- 人工接受需要明确用户动作和记录，不能变成自动审核通过。
- 移除 CN/VN 数字 4→6、PH 13→12 的无差别替换。产品原生文字/商标/印花与外围宣传水印需区分。

## 状态、持久化与恢复

每任务稳定 run_id；每资产保存 status、当前候选、所有候选历史、审核记录、修复理由和停止原因。结果新增 run_dir、进度事件、调用计数等信息。状态至少区分 succeeded、failed、pending_audit、audit_error、quality_failed、needs_input、budget_exhausted、accepted（聚合层可归并但资产不能混淆）。

有 output_dir 时使用本地 SQLite 检查点和原子文件保存；无 output_dir 时允许内存图执行，明确不具备跨进程恢复。图状态不存密钥/配置凭证，不存原始图片字节；保存文件引用及哈希。恢复从指定任务目录继续，用本次提供的配置获取凭证，并校验输入/文件完整性及兼容版本。已保存候选的审核恢复不得调用生成器。

生成节点与审核节点分离。持久化任务输入素材，避免原始素材移动导致恢复失败。记录 API 意图与提交情况；供应商支持时才可宣称幂等。调用已提交但未保存响应的崩溃窗口进入不确定状态/人工处理，不能自动重放收费请求。并发恢复同一任务必须互斥。

取消保存已完成节点与候选，恢复继续未完成节点。阶段事件可用于桌面展示，UI 只在 Tk 主线程更新。图节点错误应转为可恢复/最终状态，不能把审核服务错误变为质量不合格。

## 推荐模块边界

- pipeline.py：保留公开入口及准备上下文的复用函数，生产执行委托图；删除旧资产修复循环。
- graph_runtime.py / graph_nodes.py：图构建、生成/审核/修复/详情组审分支；所有输出类型共用。
- execution.py：ExecutionPolicy、ProgressEvent、预算与执行上下文；由引擎角色统一定义。
- run_store.py：SQLite 检查点生命周期、任务锁、候选及输入文件、恢复/人工接受。
- models.py / selection.py / quality.py / prompt.py / vision.py / compliance.py：可验证性、局部反馈修复、产品保真及审核协议。
- transport.py：在每次实际 POST 前扣减持久化预算，HTTP 重试也计数；图逻辑重試不能绕过预算。
- desktop.py / desktop_runtime.py / __main__.py / contracts.py：新状态、恢复入口、进度、人工接受、结果 v2 与 v1 阅读兼容。

模块名称允许由主协调者在实施时统一调整，但边界、验收和用户约束不可暗改。

## 调用与修复预算

质量修复预算和审核服务重试预算分别计数；默认审核异常最多额外重审 2 次；HTTP 保留最多 3 次尝试。整单预算是最终边界，必须在实际提交前预占，恢复和多节点共享。普通任务允许配置上限，不将本次开发预算硬编码到产品默认值。

本次真实验收全程累计：生图实际 API 提交最多 10 次，视觉实际 API 提交最多 30 次，包含 HTTP 重试、格式纠正、场景/融合及修复。所有 live 运行共享单独持久化账本，耗尽停止，不自动补充。下载图片不计生图提交。

修复提示词必须包含具体失败对象/指标及证据，约束原始商品身份，解释上一候选仅用于定位错误；不得让它替代原始身份素材。参考容量不足时保留必需原图，明确报告候选只能文字反馈。保存每次审核以比较修复效果，不能只保存最后一个分数。审核协议错误纠正必须覆盖聚焦复核的 ID 校验。
