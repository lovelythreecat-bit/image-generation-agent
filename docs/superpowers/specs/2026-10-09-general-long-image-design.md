# 通用图文长图设计

日期：2026-10-09

状态：设计待审阅，尚未修改产品代码。

替代：`2026-10-09-product-detail-long-image-design.md`。

## 已确认目标

用户要求项目支持完整图文长图：自动规划内容、生成配图、统一排版，导出整张长图。淘宝商品详情是最初的例子，用户已明确要求第一版覆盖通用场景，不限于某个电商平台。

第一版场景为：商品详情、品牌介绍、活动宣传、使用教程、功能或参数对比、自定义图文介绍。这些场景共用一个内容规划与排版流程，场景只影响段落组织、视觉角色及适用的审核规则，不各自建立一套生成管线。

成功标准：用户输入主题、介绍或创作要求，按需添加素材，即可得到有明确内容顺序、风格统一、中文清晰的完整长图，能够滚动预览，并导出整图、分段图片和切片。失败、候选及人工接受的状态准确传递，任务可以恢复。

## 方案与边界

采用 **模型规划内容及生成配图，程序绘制文字并排版合成**。长图不受生图模型单次图片长宽比限制：模型生成常规尺寸配图，Pillow 负责最终长画布。

直接让模型生成极长图片会受尺寸和中文质量限制；生成含文字的分段海报再拼接也难保证原文及跨段文字样式。因此第一版将页内标题、正文、步骤、表格和用户指定文案交给本地绘制，商品本身的图案或标签仍按素材保留。

排版模块接收通用内容区块，不依赖平台、商品名称、商品分类或某种审核结果。不同场景通过相同区块组合出页面，不引入任意 HTML 执行、自由拖拽编辑器或 Web 服务。

## 当前项目与接入原则

项目已有多素材分析、图像生成器、商品证据选择、逐图审核与修复、LangGraph 检查点、预算台账、候选保存、CLI、Python API 及中文 Tkinter 桌面工具。

现有 `CreationRequest` 要求商品名称、分类、素材和电商平台；现有 `detail_page` 固定生成 scene、feature、closeup 三张图。通用长图不能用虚构的商品字段或平台名来满足这些校验。

新增独立的 `LongImageRequest`、`LongImagePlan`、`LongImageResult` 和对应 API，保留旧商品请求及三图功能。复用现有生成器、传输协议、图像读取、结构化响应处理、预算、原子存储和候选机制。商品场景复用原商品分析及审核工具；其他场景使用内容与素材一致性审核。只提取必要的共用操作，不重构无关模块。

边界为规划器（输入及证据→要求表/区块/图槽）、图槽处理（槽适用要求→候选与审核）、纯本地渲染器（文本/字节/选项→像素及布局检查）、长图编排（调用归属、状态聚合及恢复）。契约模块只做 DTO 和媒体绑定，存储共用层只做按类型序列化、哈希及原子文件操作；不引入插件框架或通用执行引擎。

## 输入与场景

`LongImageRequest` 包含：

- `scene`：`product_detail`、`brand_intro`、`promotion`、`tutorial`、`comparison`、`custom`。
- `title`：必填主题，1–120 字。
- `content_brief`：必填介绍或创作要求，最多 20000 字。
- `materials`：0–8 张可选素材，沿用已有 `MaterialInput` 与 `ImageSource`。
- `style_hint`：可选风格要求；用户明确要求优先于默认风格。
- `product_context`：商品详情必填，其他场景可选；包括商品名称、分类、可选平台、展示方式和模特偏好。平台为空表示通用商品介绍；平台只能是现有支持的平台之一。
- `product_specs`：可选有序名称和值列表，最多 30 项。
- `service_notes`：可选售后说明，最多 10 项。
- `required_copy`：可选有序原文列表，每项含稳定 `requirement_id`、原文 `text` 和可选的段落用途；用于需要逐字展示的句子，不要求用户重复填写已提供的标题、参数或售后。桌面可从内容要求中的明确原文指令提取并展示此列表。
- `selection`：沿用 `SelectionSpec`，默认 `auto`；仅商品场景允许 `explicit` 及主体、必需/偏好/排除要素 ID。显式选择必须在调用时携带产生这些 ID 的同一 `MaterialAnalysis` 快照。
- `options`：`width`（长图宽度）、`theme`、`slice_height`、`font_path`（中文字体路径），均为本地渲染设置。
- `image_model`、`image_size`、`output_dir`、`request_id`：沿用已有配置和输出约定。

商品详情要求至少一张真实商品素材，以继续保证商品外观。其他场景允许纯文字输入，由模型规划示意配图或使用文字区块。用户要求准确复现品牌标识、人物或界面却没有相应素材时，提示补充输入，不能生成替代品后称为准确复现。

参数、认证、优惠、日期、联系方式和售后承诺不作为通用必填项。有明确输入才使用；用户要求必须展示某个具体值却没有提供时，显示需要补充输入，不填占位值。

场景默认结构只是策划参考：

| 场景 | 常用内容顺序 |
| --- | --- |
| 商品详情 | 首屏、核心卖点、场景、细节、已提供的参数及售后 |
| 品牌介绍 | 品牌主题、理念、产品或服务、优势、已提供的联系信息 |
| 活动宣传 | 活动主题、亮点、已提供的时间地点、参与方式 |
| 使用教程 | 目标、准备、按顺序的操作步骤、注意事项 |
| 功能对比 | 对比对象、共用维度、逐项差异、总结 |
| 自定义介绍 | 按用户目的组织标题、图文、要点、表格和收尾 |

教程中的具体界面、型号操作、活动信息和对比参数只能依据用户输入或素材。模型可以组织表达和补充一般解释，不编造用户未提供的专属事实。所有场景均保留现有用户营销文案政策：不对用户声明追加证明要求、弱化措辞或免责声明。

## 规划与内容区块

`LongImagePlan` 保存版本、输入指纹、场景、页面主题、统一视觉方向、要求表、独立 `image_slots` 和有序 `sections`；商品计划另含 `analysis_ref`（analysis_id、快照内容哈希、发现指纹）及已解决选择摘要。每个区块包含稳定的 `section_id`、版式角色、有序文本单元、表格行和 `slot_ids`；文本单元包含类型（标题/正文/要点/单元格）、文本、来源引用和覆盖的 `requirement_ids`。区块不内嵌另一份生成槽定义。

通用版式为首屏、图文、要点列表、步骤、表格、收尾。商品参数表和功能对比表都转换为同一个表格区块；售后或联系方式转换为普通列表或收尾区块。

配图策略明确区分 `source`（原素材）和 `generate`（生成配图）；无图的区块用空 `slot_ids` 表示 `none`。一个生成配图槽可以被多个区块引用，避免重复计费；引用原素材不视为生成成功。原素材中的界面、品牌图或标注信息可以原样排版。

图像槽的最小契约如下，ID 均为任务内稳定 ID：

| 字段 | 语义 |
| --- | --- |
| `slot_id`, `source`, `required` | 唯一 ID、`source/generate`、是否必须有可用字节；任何实际引用的槽必须为 required，第一版不导出带空图槽的页面 |
| `material_ids`, `role`, `prompt` | 原素材/生成参考素材 ID、用途、生成提示；source 只允许一个素材 ID 且 prompt 为空，generate 可无参考素材 |
| `aspect_ratio` | generate 必填，限 `1:1/3:4/4:5/9:16/16:9`；source 保留原图比例 |
| `requirement_ids`, `section_ids` | 此槽适用的视觉要求和引用它的区块；必须与区块反向引用一致 |

首次生图前拒绝重复 ID、悬空素材/区块/要求引用、未引用槽、超过六个生成槽及模型协议不支持的比例。比例用已有能力校验，不静默换成另一比例；排版宽度不作为生图比例。共享槽的视觉要求必须同时相容，不相容时拆槽，仍受六槽上限约束。

默认规划 4–8 段；明确的用户步骤或内容结构可使用 2–12 段。最多 6 个不同的生成配图槽；超过此限制时合并说明或使用原素材、文字区块，不能静默丢弃用户要求。不能容纳时返回需要调整输入。

要求表区分 `page_text`、`section_text` 和 `slot_visual`。每项有 `requirement_id`、`required`、输入字段 JSON Pointer 或 brief 的字符区间（半开区间、Unicode 码点计数）、输入原值，以及目标区块/图槽 ID；文字条目另有 `order` 和 `occurrences`（默认 1）。页面要求可分配给任一区块，区块要求绑定指定区块，视觉要求仅绑定适用图槽。原生商品标签、图案及结构归 slot_visual；例如本地首屏“10 月 12 日开售”归 section_text，不要求生成图片包含该句。

规划先建立要求表，再组织区块和图槽。标题、已提供且要求展示的参数/售后及 required_copy 由程序直接建立来源和原值；brief 中明确要求逐字展示的文案提取为带原文区间的条目，在规划视图中显示。明确标为“原样/必须展示/文案”的引号片段由本地预处理纳入，模型可补充识别未加引号的原文要求，但不得删除、重写这些已建立条目。普通创作指令不自动作为页内文案。表格行来源指向输入字段或原文；模型补充表达单独标记 `model_authored`。

首次生图前，本地检查每项必需文字要求均有目标文本单元，值与输入原值逐码点相等，数字和日期不归一化、不改写；条目有序时按区块及文本单元阅读顺序验证。默认每项展示一次，只有输入明确要求重复时记录具体次数；相同文字的不同要求 ID 不靠子串计数代替验证。渲染后的文本布局记录再次验证这些单元确实绘制、顺序和次数一致且未截断；排版换行不改变原始文本值。遗漏、替换或错误分配产生 `plan_invalid`，在首次生图前拒绝；不靠整图 OCR 或新增付费审核证明原文存在。

商品选择/证据编译器的长图适配只接收该槽的 slot_visual 条目与选中商品证据；完整 brief 和 page_text/section_text 不传入逐图 must_show、质量判断或修复提示。视觉风格单独传入。视觉审核仍检查商品原生标签，不因配图缺少本地文案而修图。

新增 `plan_long_image` 视觉阶段，可按配置单独路由；未配置时使用已有 `stages.vision`。规划接受文字和可选素材，复用现有结构化响应与一次格式纠正机制。普通商品任务不增加调用。

输入指纹覆盖内容、场景、素材哈希及提示、商品上下文、selection、required_copy、风格、参数和售后。宽度、切片高度、字体等本地布局设置形成单独的渲染指纹，改变这些设置不需要重新生成图片。修改影响内容的输入则使规划过期。

`LongImagePlanningResult` 返回 `schema_version=1.0`、`planning_id`、`status=ready/needs_input/failed`、可空 plan、可空 material_analysis、issues、error_info、warnings、usage 和执行记录引用。只有 ready 且无阻断 issue 的 plan 可生成。商品发现沿用真实素材、主体、事实和要素 ID；完整计划输入指纹含选择，发现指纹只覆盖发现实际输入（素材及提示、商品上下文、brief、风格等），不含选择及布局设置。显式选择提交在 request.selection，快照提交在 API 的 analysis 参数，规划结果可提供此快照；校验快照内容哈希、真实 ID 和发现指纹，不填虚构平台。相同发现输入下仅改变选择可复用发现快照并重新解析选择/规划；修改发现输入必须重新分析。可信规划记录中的快照、选择及证据解决结果完全匹配时 create 复用这些结果，不重复发现/验证；不匹配则在生图前拒绝。

通用 issue 含 `issue_id`、`code`、`message`、`blocking`、`field_refs/material_ids/source_ref` 及 `resolution=update_fields/add_materials/select_product`，可选 choices 只引用当前快照的真实 ID。例如缺少被明确要求展示的活动日期指向 content_brief，要求精确品牌标识却缺素材指向 materials。用户更新对应输入后重新规划；不提供假日期、占位值或猜测 ID。商品选择界面复用已有选择组件并携带同一快照；其余问题显示字段和补充动作。

外部 plan/analysis 在生成前重新执行 Schema、来源原值、素材哈希、输入指纹、ID 引用与选择校验。指纹不是信任证明：商品证据仍执行现有验证；服务生成并保存的规划可按记录中的内容哈希复用，外部传入且不匹配该记录的 plan 不能冒充已验证规划，拒绝并要求调用 analyze_long_image 重建。needs_input 的计划草稿仅供展示，不是可执行 plan。

## 配图、风格与审核

配图按规划中的独立图像槽串行处理。复用配置中的图像模型别名、参考图容量、并发限制、远程图片解析和请求提交日志。

商品场景复用商品分析、选择及证据验证；商品上下文平台为空时采用通用商品详情约束，有平台时采用适用的详情配图规则，不误用主图白底规则。每个图像槽按其用途编译证据和审核要求，不进入固定三张的成组审核。

非商品场景检查配图是否符合区块意图、是否保留明确要求的素材主体或标识、是否包含未要求的水印或误导性内容。普通说明插图不套用商品身份、服装结构或“全商品必须可见”等约束。

新增 `audit_long_image_asset` 视觉阶段，默认使用已有视觉路由。图像审核仍可定向修复，次数及调用限额沿用 `ExecutionPolicy`。文字段落和原样使用素材的区块不触发生图模型审核。

通用审核使用独立报告：`slot_id/candidate_id`、`checks[{requirement_id?, kind, passed, reason, severity}]`、`passed`、`repairable` 和可空 `repair_prompt`，kind 限用途、指定主体/标识、未要求的文字/水印、风格，severity 为 info/warning/critical。一般用途/水印检查可无 requirement_id，检查指定要求时必须绑定该槽真实 ID。生成图本地先验证可解码、非空、尺寸和比例；技术失败不能被视觉评分覆盖。技术检查通过、所有必需视觉要求有通过的 check、无 critical 缺陷才 passed；可修复的失败在预算/次数内修复，否则 quality_failed。未知或缺失适用要求 check、非法响应经一次格式纠正仍失败为 audit_error；未调用审核为 pending_audit。缺输入返回 needs_input，不以修复猜测。source 仅有本地读取及布局检查，不伪造视觉报告。商品报告继续采用现有商品审核，但同样只覆盖该槽适用要求；通用报告不填商品、服装或平台分数。

所有生成图共享规划中的视觉方向：配色、光线、背景、人物设定及插画或摄影风格。审核通过的适用图片可作为后续视觉参考；必需原素材证据优先，参考容量不足时使用共同文字设定并记录警告。

## 本地排版与导出

通用渲染器输入为内容区块、主题、图像槽字节及选项，输出布局数据、排版段落、整图及切片。不访问模型、选择候选或修改预算。

默认宽 750 像素，允许 400–2400 像素；默认切片高 1500，允许 500–4000。宽度仅为项目默认值，不宣称为平台要求。长图最高 16000 像素且总像素不超过 2400 × 16000；超出时报告布局错误，保留已生成配图，不截断内容。

主题为 `auto`、`clean`、`warm`、`premium`，默认自动结合用户风格、素材与场景选择。统一背景、前景、强调色、文字层级、边距和段间距；保证可读对比度，不强制所有场景使用电商视觉。

先测量文字再确定段高，支持中文换行、长英文串、数字单位、列表、步骤编号和两种表格。宽 750 时正文默认不小于 26 像素，随宽度等比调整；不通过无限缩小字号容纳内容。配图默认等比完整展示，避免裁掉重要主体。

中文字体优先使用用户指定路径，否则查找支持中文的已安装字体。找不到字体时在付费调用前报告具体错误。用字体 cmap 验证所有输入待展示字符，规划后再验证新增字符；按用户指定字体、系统中文字体的固定查找顺序逐字符回退，无覆盖时报 font_missing_glyph，不输出方框字。渲染指纹包含实际使用字体文件内容哈希及回退顺序、解析后的主题颜色/字号/间距、宽度、切片高度和渲染器版本，不只记录字体路径。

整图、段落和切片默认 PNG。切片按连续像素范围划分，按顺序拼接后应与整图像素完全一致；排版段落是语义分段，切片是上传或分发用的等高分割，两者分别展示。第一版不增加 JPEG 编码设置。

布局检查覆盖文字越界、区域重叠、空段、缺图、表格列宽和整体尺寸。分段生成后再合成并及时释放中间图片；桌面预览使用缩略图或可见区域，不同时保留多份原尺寸长图。

## 执行、结果与恢复

新增 `analyze_long_image(request, config, *, analysis=None, policy=None, on_progress=None)`、`create_long_image(request, config, *, plan=None, analysis=None, planning_record=None, policy=None, on_progress=None)`、`resume_long_image(run_dir, config=None, *, on_progress=None)`、`accept_long_image_candidate(run_dir, slot_id, candidate_id)` 和 `render_long_image(run_dir, *, render_options=None, on_progress=None)`。接受操作通过下文的衍生修订流程持久化接受记录并刷新交付，无需模型配置。纯本地内存入口为 `render_long_image_memory(plan, selected_assets, *, render_options=None)`，接收已验证规划及带状态的选中资产，返回同一结果契约，无持久恢复能力。现有 `create_images`、`resume_images` 及旧商品模型不改变行为。

独立 analyze 是单独有界的规划任务，创建自己的 BudgetLedger、固定 policy、planning_id 和规划执行记录；使用 output_dir 时持久化，否则使用内存记录。不把旧 analyze_materials 的无台账行为当作长图预算实现。重复点击规划会产生新 planning_id，各次用量在桌面规划历史中保留并合计展示；配置 shared_ledger_path 时共享上限同时约束这些任务。生成任务使用自己的固定台账；无 plan 时它自己规划，该用量计入生成任务。已有 ready plan 和可信 planning_record 匹配时不再次付费规划，也不把规划的调用重新预占到生成台账。

返回 usage 分为 `execution`（当前任务真实预占次数）、`linked_planning`（按唯一 planning_id 去重的引用用量）及 `display_total`（两者和），并保留 planning_id；反复恢复或导出不重复累加。独立规划和生成的单任务上限分别生效，display_total 不冒称同一单任务上限；共享台账才是跨任务硬上限。外部 JSON 不得声明可被信任的计费记录；适配器按本地记录绑定，未绑定的历史规划用量标为 unavailable，不编造零或总数。policy 和 ledger 在恢复时保持原值，丢失/损坏台账不得重置计数。

所有实际视觉 POST（发现、选择证据验证、规划、审核及各自格式纠正）必须在所属 ledger 的 `call_scope(..., "vision")` 内，记录阶段/槽/尝试；HTTP 重试每次实际提交都计数，格式纠正也占一次视觉调用。每次生图/修复使用稳定 `operation_id=run_id/slot_id/attempt_no`，在 `call_scope(ledger, "image", store, operation_id)` 内提交，不能仅调用生成客户端。先保存 started 与尝试，再由 reserve_post 在预算事务中预占，并在发送前持久标 submitted；台账与日志不假定为同一事务，其间中断也采用不确定提交保护。响应 raw 原子落盘、saved 日志（raw 哈希及尝试/槽快照）写入后才进入候选保存及检查点。恢复遇 saved 复用 raw，遇 started/submitted 且无持久响应保守返回 generation_uncertain，禁止自动重复收费；已保存候选中断只重审或本地渲染。

独立的长图 LangGraph 编排为：准备及预检 → 规划或复用规划 → 逐槽准备、生成、保存、审核及修复 → 渲染区块 → 合成整图和切片 → 汇总。共用生成操作、存储和预算工具；不调用完整商品任务多次来生成各段。

`LongImageResult` 采用独立 1.0 Schema，记录 `task_type=long_image`、整体状态、规划、issues/error_info、配图资产、排版资产、成品、切片、页面检查、用量、警告和输出错误。各产物包含来源、状态、稳定 ID、宽高、像素输入哈希、元数据修订版本及本地文件引用；成品额外含 `availability=current/stale/absent`。DTO 通过独立 blob ID 交付字节，不泄露本地路径。

原样素材和本地合成不伪造模型生成尝试或审核报告。source 槽用 `available/missing/invalid` 表示本地字节状态，不标模型生成 succeeded；missing/invalid 聚合为 failed 并带文件错误。使用原样素材不宣称自动验证了素材中的宣传事实；它是否被用作素材由用户授权及规划决定。

整体状态和当前成品按下表聚合，不复用旧三图“混合 accepted/succeeded 为 partial”的聚合器。源素材无需审核状态；只聚合被引用的槽。所有 required 字节都可用且本地检查/输出通过才可有 current 成品。候选严重程度固定为 `generation_uncertain > budget_exhausted > audit_error > pending_audit > needs_input > quality_failed > failed`，并保留各槽详细状态；accepted 不能掩盖另一槽的候选状态。

| 条件（上方行优先） | 整体状态 / 当前成品状态 | 成品交付 / CLI 退出码 |
| --- | --- | --- |
| 输入/规划有阻断问题 | needs_input（缺输入）或 failed（非法计划） / 无 | absent；3 或 1 |
| 布局、文字覆盖、合成或成品/段落/切片任一必需保存失败 | failed / 无有效成品 | absent；旧产物只能 stale；1 |
| 任一 required 槽无可用字节 | 按上述严重程度取阻断槽状态，无明确状态则 failed / 无 | absent；沿用状态码：7/6/5/5/3/1/1 |
| required 字节齐全，但有未通过/未审核生成槽 | 最严重候选状态 / 同一状态 | current 候选整图及分段/切片；7/6/5/5/3/1/1 |
| required 字节齐全，所有生成槽 succeeded 或 accepted，至少一个 accepted | accepted / accepted | current；4 |
| 零生成槽，或全部生成槽 succeeded；本地检查及输出通过 | succeeded / succeeded | current；0 |

语义段落按自身依赖槽计算状态，整图及切片继承全页状态；独立原始配图保持自己的状态。完整长图不使用 partial 表示一槽接受，其余通过。保存失败行只指请求需要交付的产物；无 output_dir 的内存交付不要求文件落盘。

即使配图成功，合成或保存失败仍必须体现在整体状态和成品错误中，不能被配图成功数量掩盖。候选状态通过界面和 JSON 传递，不额外绘制审核水印。

任务元数据新增明确的任务类型。旧 version 1/2 商品任务及结果无类型字段时仍按商品契约解释；新增长图任务保存独立请求、规划、输入、图像槽、阶段、生成提交日志与渲染引用。读取任务与桌面历史结果均先按 task_type 分派请求/结果 Schema 和文件加载器，未知类型/版本明确报错；旧类型缺失不能被长图字段猜测改派。各加载器沿用任务根目录内相对路径与哈希验证，通用存储层允许空 materials，不通过虚构旧商品字段保存。

输入字节、候选及渲染结果均保存哈希。已提交生图请求的不确定状态继续采用现有处理，不自动重新收费提交。已完成的图像槽在恢复时复用；本地排版失败恢复不增加模型调用。

像素缓存键与交付元数据分开。像素键包括 plan 内容哈希、选中字节哈希、渲染指纹；槽选中 candidate_id、审核状态/报告或接受记录变化时增加 `asset_revision`，全页 `delivery_revision` 重新聚合，即使字节不变。同一字节 pending_audit→succeeded 或 quality_failed→accepted 可复用像素，但必须更新段落、整图、切片、清单和 DTO 的状态。选中字节或布局改变才重绘相应像素。预算台账不重置；纯本地重建没有图片或视觉调用。

持久衍生修订按固定顺序提交：先原子写入修订意图，记录目标选择/状态/选项和新 revision，标旧清单 stale；再保存槽元数据，生成或复用经过哈希验证的像素到新 revision 目录并写页面检查；全部必需产物成功后原子替换当前清单指针，最后完成检查点并清除意图。加载时只要有未完成意图，旧清单不得作为 current；中断恢复按意图完成本地修订，不发模型请求。失败保留旧文件供查看但标 stale，不带 succeeded/accepted 的当前交付资格。审核节点、接受入口和本地重排版都使用这一简单存储流程，不引入通用事务引擎。

`render_long_image` 专门读取已保存的 plan、选中候选及 source 字节和状态，仅允许覆盖 `width/theme/slice_height/font_path`，其余字段拒绝并提示重新规划。它可用于已终止任务和超高/字体/保存失败任务，不走旧 resume 的提前返回，也不创建网络客户端、不要求 API 密钥或模型配置。每次覆盖保存为本地渲染修订，theme 仅改变本地主题，style_hint 属内容输入不能在此修改。缺失/损坏素材或候选返回结构化输入/文件错误，不自动生图；用户修复本地输入后可重建。恢复若只剩衍生修订则直接走此入口；需要生成或重审时 resume 才加载模型配置。

无需输出目录的 Python 调用支持内存结果，但持久恢复必须有任务目录。字体、标题及非法输出路径等能确定的错误在模型调用前验证。

## 外部契约与本地边界

新增独立 `LongImageRequestDTO`、`LongImagePlanDTO`、`LongImagePlanningResultDTO` 和 `LongImageResultDTO`，均为 `schema_version=1.0, task_type=long_image`；plan 还记录规划器版本，不能混用旧商品结果 Schema。请求 DTO 包含场景/文案/商品可选上下文/选择/渲染尺寸及主题/模型设置，materials 沿用 material_id+media_id，通过可信适配器绑定 ImageSource。规划 DTO 保留要求来源、图槽与区块；规划结果 DTO 保留 issues、MaterialAnalysis、用量及 planning_id，记录引用只含不透明 record_id，不能提交台账路径。计划及快照由 record_id 绑定时对比已存内容哈希，不接受客户端伪造的已验证标志。

`font_path/output_dir/run_dir`、素材本地路径、候选文件路径及配置/台账路径不进入外部 DTO。外部请求不接受这些字段；font_id 或记录 ID 只经可信本地适配器解析为已允许字体/任务目录，未绑定时报错。桌面和本地 Python 参数可直接使用受校验的本地路径；CLI 的 --font-path/--output-dir/--run-dir 是本地参数，与请求 JSON 分开，不能在媒体 JSON 中绕过绑定。

结果 bundle 包含 DTO 和 blobs，统一前缀为 `long_image/{内部run_id或内存生成的bundle_id}/{delivery_revision}/`，后缀为 `asset/{slot_id}`、`section/{section_id}`、`page`、`slice/{index}` 或 `candidate/{slot_id}/{candidate_id}`。不使用未经校验的用户 request_id 组成 blob ID。每个 blob 引用含 mime_type、byte_length、sha256，ID 唯一且不能被当作文件路径。所有字节对应 DTO 中自己的状态/availability；候选字节不表示通过，stale 不作为 current 下载。DTO 转换递归移除本地引用和路径型错误上下文，不仅剥离顶层 run_dir。Schema 导出同时覆盖这四个新契约并保留旧四个导出。

## 桌面与 CLI

桌面任务模式增加“图片创作 / 图文长图”。长图模式展示场景、主题、内容要求、可选素材及折叠的尺寸和风格设置。仅商品详情显示商品信息和可选平台；其他场景不要求填写商品字段。

沿用当前中文字体、表单样式、按钮、后台任务、取消和错误展示习惯。切换模式保留各自输入，清除不匹配的分析或策划引用，不把商品旧分析套到新内容。

“分析素材”在长图模式显示为“规划长图”，展示段落、文案、素材用途和预计生成配图数。用户修改输入后重新规划；第一版不新增拖拽或区块编辑器。“生成图片”在该模式显示为“生成长图”。

规划为 needs_input 时展示结构化问题及补充字段，商品问题显示当前分析的主体/要素选择；提交选择时携带同一快照，再规划得到 ready。规划面板展示独立规划用量和记录，生成后同时展示生成用量及去重总计。用户打开长图历史任务可修改宽度、主题、切片高度、字体，点击“重新排版”调用纯本地 render；文字内容、素材或视觉风格修改仍需重新规划。

结果可切换整图、语义段落、切片和原始配图。整图支持缩放、适应宽度和纵向滚动；保持现有打开输出目录、查看候选、接受候选和恢复任务的操作，按任务类型路由。

CLI 新增 `long-image analyze`、`long-image create`、`long-image resume`、`long-image accept` 和 `long-image render` 子命令，使用独立参数及请求 JSON。create 可绑定规划记录及同一分析快照；render 只接任务目录和四项白名单本地选项，无需密钥。旧 `create --output detail_page` 不变。JSON 请求继续通过媒体 ID 绑定素材，不能包含未验证的文件路径。

CLI 退出码沿用现有状态约定，但最终合成失败不能仅因配图成功而退出 0。桌面和 CLI 说明预计配图调用数；一张最终长图不等于一次生图费用，规划、审核和修复另计。

## 验证与交付

预计新增长图模型、规划、渲染、编排与契约模块；调整存储共用层、配置视觉阶段、桌面入口、CLI 和公开导出。同步更新独立 JSON Schema、README 与各场景示例。

验证包括：

1. 请求与 Schema：六种场景、无平台无素材的非商品输入、商品素材要求、字段边界、旧商品请求及历史任务兼容。
2. 规划：各场景内容顺序、引用完整、原文及数字保留、无额外专属事实、共享配图槽、输入改变使规划失效；漏掉原句在首次生图前拒绝，日期仅本地展示一次，商品原生标签仍受视觉审核；两商品素材问题可用同一快照显式选择，缺活动日期不编造，篡改/过期 plan 拒绝。
3. 生成与审核：商品和通用审核分流、原素材与文字段不调用生图、模型路由、预算、修复及候选状态；独立规划及一次格式纠正计数、可信计划复用零规划调用、HTTP 重试计数、submitted 中断不重复生图、用量去重与共享上限。
4. 渲染：真实中文字体、表格、长内容、多宽度、无方框字、边界检查、最高长度、内存上限及像素一致的切片。
5. 恢复：生成保存后中断、合成中断、审核失败恢复、人工接受后重建、输入文件损坏、预算不重置和旧任务不受影响；同字节重审/接受更新所有状态，接受后渲染失败仍 failed，修订各提交边界中断不交付旧清单，零调用恢复本地修订。
6. 入口：桌面模式切换、滚动预览、取消、CLI 子命令、媒体绑定和 Python API 内存结果；无密钥重排版终止/超高任务，白名单拒绝内容覆盖，字体内容改变刷新指纹，六场景 DTO 无路径、blob 唯一、旧无类型结果正确加载、未知版本报错。
7. 视觉验收：离线渲染至少商品详情、活动宣传、步骤教程三份实际长图，查看整图及分段，检查中文、层级、段落连贯和表格。

执行相关测试、已有回归测试与 Ruff。离线验证不代表真实模型出图质量；真实 API 验证另行执行并明确记录。设计和本地验证不自动读取密钥并提交付费调用。

## 第一版范围外
